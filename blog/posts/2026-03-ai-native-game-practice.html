从零构建 AI Native 移动端游戏：GLM API 与 Cloudflare Serverless 的工程实践

AI Native 发布于 2026-03-20 · 预计阅读 6 分钟 · 作者：张瀚 (ZZDR1023)
H5 Canvas DeviceMotion API GLM API Cloudflare Workers Cloudflare D1

一、背景：为什么不是简单的“套壳 AI”？

在很多所谓的 AI 游戏项目中，大语言模型往往只充当一个悬浮在侧边栏的对话框或者剧情复读机，游戏核心玩法与模型处于完全割裂的状态。

在开发《光球潜入（Cyber Infiltration）》之初，我的目标是验证一种真正的 AI Native 交互闭环： 玩家在手机上通过物理体感（重力陀螺仪）操控光球躲避探测网络、收集能量核心；游戏结束时，系统不使用死板的固定模板评分，而是提取玩家的真实轨迹特征（如闪避频率、存活时长、关键决策偏好），通过 Prompt 动态注入大模型，生成带有强烈赛博朋克黑客风格的动态任务评估报告与专属剧情文案。

💡 核心设计理念

让大模型成为玩法结算的“裁判与叙事官”，而不是与主玩法脱节的聊天插件。

二、系统总体架构

为了保证移动端极低的网络延迟和零运维成本，整个技术栈采用了现代 Serverless 方案：

  • 前端层 (Client)：纯原生 JavaScript + HTML5 Canvas 绘制 60fps 粒子流光效果，使用 DeviceMotionEvent 监听手机倾斜重力感应。
  • 托管与加速 (Hosting)：Cloudflare Pages 全球 CDN 加速，国内无需代理秒开。
  • 无服务器计算层 (Serverless Compute)：Cloudflare Workers 编写边缘计算路由，负责 API 鉴权、速率限制与 LLM 接口封装。
  • 智能决策层 (LLM Layer)：接入智谱 GLM API，根据量化指标输出结构化 JSON 结算文本。
  • 数据持久化 (Storage)：Cloudflare D1（Serverless SQL 数据库）记录全球玩家排行榜与结算记录。

三、核心难点：玩家行为特征到 Prompt 的映射

大模型无法直接理解一万帧的原始坐标轨迹数据。我们需要在客户端将物理游戏过程抽象为高信噪比的行为特征向量（Feature Vector）：

javascript // 行为数据提取 
// 结算时提取的行为特征上下文
const sessionMetrics = {
  durationSeconds: Math.floor(gameTime / 1000),
  stealthRate: (stealthFrames / totalFrames * 100).toFixed(1) + "%",
  dangerCloseCount: nearMisses,        // 极限擦弹次数
  coreCollected: collectedCores,      // 核心收集数
  dominantStyle: calcPlayStyle(turns, speedVariance), // 风格：激进突进型 / 稳健潜行型
};

在 Worker 边缘函数中，我们将该特征注入格式受控的系统提示词（System Prompt），并要求 LLM 输出强类型的 JSON：

typescript // Cloudflare Worker 结算请求 
export async function onRequestPost(context) {
  const { metrics } = await context.request.json();

  const prompt = `你是一个赛博朋克安全AI主机。根据入侵者的作战遥测数据：
- 潜入时长: ${metrics.durationSeconds}s
- 隐匿率: ${metrics.stealthRate}
- 极限脱险: ${metrics.dangerCloseCount}次
- 风格判定: ${metrics.dominantStyle}

请以冷酷或赞赏的主机口吻，输出一段不超过80字的入侵评估和给予代号。
返回严格JSON格式：{"codename": "...", "verdict": "..."}`;

  // 调用 GLM API...
}

四、高可用设计：Fallback 熔断降级机制

在真实网络和移动端弱网环境下，第三方大模型可能会出现偶发超时或限流（Rate Limit）。对于游戏而言，玩家在结算页绝不能看到转圈崩溃。

⚠️ 工程防御哲学

AI 是锦上添花的能力增强，业务主流程绝不能因为 AI 服务波动而中断。

我们在 Worker 端设置了 3.5 秒严格超时控制。一旦 GLM API 超时或返回非 200，触发内置的规则引擎算法库（基于分数区间的本地赛博文案生成池），瞬间返回确定性的降级文案，同时在后台记录告警日志。这种防御设计让游戏在极端网络条件下的可用性达到了 99.9%。

五、总结与未来演进

通过《光球潜入》的研发，我总结出三条关于 AI Native Web 开发的黄金法则：

  1. 特征提纯比全量上下文更重要：精炼的行为量化指标比盲目把所有动作喂给模型更加经济且高效。
  2. 边缘 Serverless 是大模型 API 的天然伴侣：Cloudflare Workers 保护了模型 API Key 不泄露，并在边缘做到了毫秒级响应。
  3. 始终设计确定性降级路径：拥抱大模型的不确定性，并用确定性的工程手段兜底。

接下来，我计划把这套结合体感和 AI 评估的机制应用到更多硬件与 ROS 机器人远程控制项目中，期待带来更具沉浸感的交互可能。
